# 地方志校订稿人名标注迁移

地方志改用校订稿时，把旧稿检索库中的人名标注逐页迁移到新稿。FastAPI + SQLite，
单容器 Docker Compose 启动，Swagger 界面（`/docs`）内置「重复人名」与
「确认冲突」示例，可直接演示。

## 迁移规则

1. **逐页提交**：`POST /pages` 接收同页旧稿、校订稿（各 ≤ 300 字）和旧稿上
   人名标注的字符区间 `[start, end)`（按 Unicode 码位计）。
2. **最短对齐为准**：以「插入 + 删除总次数最少」的对齐为准。改字视为一删
   一插，因此最短对齐恰好是全部 LCS（最长公共子序列）对齐，代价为
   `n + m − 2·LCS`（响应中的 `edit_ops`）。
3. **可用 vs 待核**：只有在**所有符合已有确认的最短对齐**中，一条旧标注都
   **逐字对应新稿同一连续区间**，它才是可用的（`auto`），并连同新区间经
   `GET /pages/{id}/index` 提供给检索库；其余标为**待核**（`pending`），
   响应附当前仍可能的候选新区间 `candidates`。
4. **编辑确认**：`POST /annotations/{id}/confirm` 确认一条待核标注的新区间。
   确认把旧新区间钉成一组锚点，随后**重新判断本页全部标注**（确认只会收缩
   对齐集合，可用标注不会回退为待核）。
5. **冲突退回**：新确认只有在**原本的最短对齐**中仍存在一种符合**全部**确认
   的方案时才生效；否则（交叉、文字不符、长度不符、非最短对齐）返回
   `409` 并保留当前结果。并发提交同样如此：确认→重判→落库在进程锁 +
   `BEGIN IMMEDIATE` 事务内串行执行，后到者基于最新结果重新校验。
6. **编辑补录**：校订稿上新添的人名由编辑按页、姓名、校订稿字符区间补录
   （`POST /pages/{id}/supplements`）。同一页、同名、同区间重复补录只记一次
   （幂等，返回 200 与既有记录）。
7. **命中合并**：按页供数（`GET /pages/{id}/hits`，`GET /pages/{id}/index`）
   把**同名同区间**的补录与可用旧标注合并为一条命中，`sources` 逐项列出
   来源类型（`annotation` / `supplement`）与编号。命中编号持久化在库中，
   `GET /hits/{id}` 可回查，重启后不变。
8. **旧标注并入**：后来变为可用的旧标注（编辑确认后）若与既有补录命中同名
   同区间，并入该命中并**沿用原编号**。启动时会把已有页（含升级前的页）
   回填进命中索引。
9. **更正补录区间**（`PATCH /supplements/{id}`）：新位置已有同名同区间命中时
   退回 `409`，`detail` 告知既有命中编号，原供数与命中不变；新位置没有同名
   命中时，若原位只剩这条补录，编号随补录移动；若原位还有其他来源，原编号
   留在原位，新位置另发编号。更正与确认并发时由同一把进程锁 + 写事务按提交
   顺序串行化，来源归属随后到者看到的最新结果判定。查询接口在一个读事务快照
   内取判定与命中，只看到完整结果。

## 快速开始

```bash
docker compose up --build
# 打开 http://localhost:8000/docs
```

`/docs` 中 `POST /pages` 有两个预置示例：

- **重复人名**：`張三還書，張三攜酒。` → `張三還書，張三張三攜酒。`
  第一处「張三」自动可用 `[0,2)`；第二处可对应 `[5,7)` 或 `[7,9)` → 待核。
  对其调用 confirm（示例体 `{"new_start": 7, "new_end": 9}`）后生效。
- **确认冲突**：`張三和李四` → `李四和張三`，两条标注都待核。先确认
  「張三」→ `[3,5)` 生效；再确认「李四」→ `[0,2)` 与之交叉，返回 409，
  当前结果保留。

补录与更正也有预置示例：`POST /pages/{page_id}/supplements`（先在 `POST /pages`
建页得到页号，如重复人名示例页为 1）、`PATCH /supplements/{id}`。补录示例把
`張三` 登记到 `[7,9)`；随后 `POST /annotations/{id}/confirm` 把第二处旧标注确认为
`[7,9)`，可在 `GET /pages/1/hits` 看到两个来源合并为同一条命中并沿用编号。
更正示例给出两种情形：新位置已被同名命中占用（409，detail 含既有编号）、
更正到空位（编号随补录移动）。

说明：按页供数只统计**可用旧标注**与补录；待核旧标注无法确定新区间，不进入
命中（仍列在 `/pages/{id}/index` 的 `pending` 中供编辑处理）。`/pages/{id}/index`
的 `pending` 候选区间与命中来自同一只读快照。

无 Docker 时本地运行：

```bash
pip install -r requirements-dev.txt
uvicorn app.main:app --port 8000
```

## 接口一览

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/pages` | 提交一页新旧两稿与旧标注，返回逐条判定 |
| GET | `/pages` | 列出全部页（可用/待核计数、版本） |
| GET | `/pages/{id}` | 一页当前判定（待核标注附候选区间） |
| GET | `/pages/{id}/index` | 检索库视图：命中（含来源明细）+ 待核标注 |
| GET | `/pages/{id}/hits` | 按页供数：仅命中列表，同名同区间来源合并 |
| GET | `/hits/{id}` | 按命中编号回查（重启后仍可） |
| POST | `/pages/{id}/supplements` | 按页补录人名（同名同区间幂等） |
| PATCH | `/supplements/{id}` | 更正补录区间；冲突 409 并给出既有命中编号 |
| GET | `/supplements/{id}` | 查看一条补录及其当前命中编号 |
| POST | `/annotations/{id}/confirm` | 确认待核标注新区间并重判本页；冲突 409 |

> `POST /supplements`（页号写在请求体中）是 `POST /pages/{id}/supplements`
> 的等价别名，便于已有调用方；`GET /pages/{id}/index` 保留旧字段
> `annotation_id` / `source`（取首个来源）并新增 `hit_id` / `sources`。

## 实现要点

- **不枚举最短对齐**（数量可指数级）：用前/后缀 LCS 动态规划表，对每条标注
  判定「其字符在所有最短对齐中是否必然逐字对应同一连续区间」。
  旧稿第 `i` 字必然对应新稿第 `j` 字 ⟺ 该对应属于某条最短对齐、且不存在
  删去 `i` 的最短对齐、且 `i` 的可对应位置唯一。
- **确认即锚点**：确认的逐字对应把两稿切成独立区间，区间间 LCS 互不影响，
  重判只需在各区间内查表，整页 O(n·m)（n, m ≤ 300）。
- **一致性校验**：全部锚点递增、同字，且各区间 LCS 长度之和加锚点数等于
  原本 LCS 长度 ⟺ 原本的最短对齐中仍有一种符合全部确认。
- **命中索引**：`hits` 存 (页, 姓名, 区间) 唯一行，`hit_sources` 把旧标注与
  补录各至多挂到一条命中。每次确认/补录/更正后在写事务内 `reconcile`：
  按当前可用标注与补录重建归属，遇到既有命中即沿用编号，清空后删除孤立命中。
  更正需要「编号随补录移动」时，先在 `hits` 行上改名/改区间再 reconcile。
- **并发**：进程内写锁串行化「确认→重判→落库」与「补录/更正→重建命中」，
  SQLite `BEGIN IMMEDIATE` + `busy_timeout` 作库级兜底；冲突方收到 409，
  已存结果不变。查询在 `BEGIN` 只读事务里同时读取判定与命中，只见完整结果。

## 遗留项

- 校订稿中**整段删去**的标注没有合法新区间，只能一直待核（任何确认都 409）；
  如需「确认已删」可再加一个状态。
- 确认记录目前只追加不撤销；如需撤销/改判，要定义回滚语义。
- 补录只校验区间不越界；人名与区间文字是否一致交由编辑判断（补录的是
  「新添人名」，可能与正文用字不同）。
- 补录目前只能更正区间、不能删除；删除需定义命中编号回收语义。
- 多副本水平扩展需把进程锁换成集中式锁（或改用支持行锁的数据库）。
- 字符区间按 Unicode 码位计；若检索库按 UTF-8 字节或 UTF-16 计，需要换算层。
